# Plan: `/pds:triage` — Insights-to-Issues Skill

## Context

After running Claude Code's `/insights` command, the user gets a rich HTML report analyzing their sessions — friction patterns, workflow wins, feature suggestions, horizon opportunities. But this analysis sits as a static report. The user wants a **repeatable PDS skill** that systematically converts insights into tracked GitHub issues across their repos, with human confirmation at every step.

The `/insights` command generates:
- `~/.claude/usage-data/report.html` — 68KB HTML report with 7 actionable sections
- `~/.claude/usage-data/facets/*.json` — 214 per-session analysis files (goals, friction, outcomes)
- `~/.claude/usage-data/session-meta/*.json` — 646 session metadata files (project_path, tools, languages)

Session-meta `project_path` fields map to real repos (stripping `/.worktrees/` suffixes), enabling issue routing.

## Naming Decision

**`/pds:triage`** — 6 characters, universally understood as "sort, prioritize, and route." Avoids collision with `/insights` (which *generates* data; triage *consumes* it). Shorter than alternatives (dispatch-insights, harvest) and more descriptive than abstract names.

## Approach

Plan-mode interactive skill (hybrid of `/pds:grill` Q&A + `/pds:inspect` procedural gathering). Six phases:

1. **Load** — Verify data exists, check `gh` auth, load dedup history
2. **Parse** — Read report.html sections, build repo index from session-meta, join facets to repos
3. **Analyze** — Cross-reference report sections with per-repo facet aggregation, propose issue groupings
4. **Walk-Through** (interactive) — Present each section's findings, user confirms/rejects/modifies
5. **Create** (interactive) — Create confirmed issues via `gh issue create`, with user approval per issue
6. **Persist** — Save report snapshot + analysis + manifest to `~/.config/pds/insights/YYYY-MM-DD/`

## Key Design Details

### Repo resolution
```
project_path → strip /.worktrees/<anything> → git remote get-url origin → parse owner/repo
```
Filter out: `.claude-mem/` paths, bare directories, `/Volumes/` paths, repos with <2 sessions.

### Issue grouping
Group by **repo first**, then by category within repo. Multiple friction points for the same root cause → single issue. CLAUDE.md suggestions → single "Update CLAUDE.md" issue per repo with checklist body.

### Deduplication
Manifest at `~/.config/pds/insights/<date>/manifest.json` records created issue fingerprints (hash of title+category+repo). On re-run, check prior manifests + `gh issue list --search` for duplicates.

### Persistence
- `~/.config/pds/insights/YYYY-MM-DD/report.html` — snapshot
- `~/.config/pds/insights/YYYY-MM-DD/analysis.json` — aggregated per-repo analysis
- `~/.config/pds/insights/YYYY-MM-DD/manifest.json` — issue creation record

### Issue body format
```markdown
## Source
Generated by `/pds:triage` from Claude Code `/insights` (DATE).

## Evidence
- [friction details / examples from report]
- N sessions affected, friction score: M

## Suggested Action
[action description]

---
*Auto-generated by [PDS](https://github.com/rmzi/portable-dev-system) /triage*
```

### Labels
Always apply `insights-triage`. Section-specific: `friction`, `dx-improvement`, `claude-md-update`, `workflow-improvement`, `enhancement`. Pre-create labels with `gh label create --force` before issue creation.

## Verification

1. Run `/pds:triage --dry-run` — should complete Phases 1-4 without creating issues
2. Verify repo resolution: worktree paths correctly stripped, observer sessions filtered
3. Verify dedup: run twice, second run should flag all issues as already-created
4. Verify persistence: `~/.config/pds/insights/` directory populated with all 3 files
5. Verify issue creation: `gh issue list --label insights-triage` shows created issues
6. Run EVAL.md scenarios manually
